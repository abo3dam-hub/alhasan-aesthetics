═══════════════════════════════════════════════════════════════════
  1. PROBLEM
═══════════════════════════════════════════════════════════════════

The deployed Vercel URL showed a blank page. Direct navigation to
/client routes like /ar returned a Vercel 404.

Root Cause:
  No vercel.json existed in the repository. Vercel detected the
  project as Vite and served the dist/ folder as static files.
  Client-side React Router routes (/ar, /en, /procedure/:slug,
  /dashboard, /auth, etc.) do not exist as actual files in dist/.
  Vercel returned 404 for those paths instead of serving index.html
  so that React Router could handle the routing client-side.

═══════════════════════════════════════════════════════════════════
  2. FIX APPLIED
═══════════════════════════════════════════════════════════════════

File Created:   vercel.json (new)

Purpose:
  Add an SPA rewrite rule so that all client-side routes are served
  through index.html, while preserving static assets.

Rewrite Logic:
  - Any path that matches static assets (/*.{js,css,png,jpg,svg,
    woff2, etc.}) is served directly from dist/.
  - Named public files (robots.txt, sitemap.xml, manifest.webmanifest,
    logo.svg, favicon.ico, favicon.svg) are served directly.
  - The /assets/* directory is served directly.
  - Everything else falls through to /index.html for React Router.

Result:
  /              → index.html → Landing page
  /ar            → index.html → Landing (Arabic)
  /en            → index.html → Landing (English)
  /procedure/*   → index.html → Procedure detail page
  /before-after  → index.html → Before & After page
  /consultation  → index.html → Consultation page
  /auth          → index.html → Auth/Login page
  /dashboard     → index.html → Admin Dashboard (protected)
  /*             → index.html → 404 Not Found (handled by React)
  /robots.txt    → static file served directly
  /sitemap.xml   → static file served directly
  /assets/*      → static files served directly

═══════════════════════════════════════════════════════════════════
  7. SPA FALLBACK VERIFICATION
═══════════════════════════════════════════════════════════════════

The vercel.json rewrite rule:

  {
    "source": "/((?!assets/|logo\\.svg|robots\\.txt|sitemap\\.xml|manifest\\.webmanifest|favicon\\.ico|favicon\\.svg|.*\\.js$|.*\\.css$|.*\\.png$|.*\\.jpg$|.*\\.jpeg$|.*\\.gif$|.*\\.svg$|.*\\.woff$|.*\\.woff2$|.*\\.ttf$|.*\\.eot$|.*\\.ico$|.*\\.webp$|.*\\.avif$).*)",
    "destination": "/index.html"
  }

How it works:
  - Uses a negative lookahead regex to match everything EXCEPT files
  - Static assets pass through to be served as-is
  - SPA routes fall through to index.html
  - React Router then handles client-side routing
